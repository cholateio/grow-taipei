# 試玩修正批次（2026-11-05）設計：老鼠咬住牛奶、風車島風電場、停電燈緩緩呼吸、後期劇本修剪

使用者 2026-11-05 試玩三局（電燈假升級上線之後）：「效果很好欸，代表方向正確了，三次遊玩都沒有發現重大失誤或體驗不佳。幾個小方向修正建議：
1. 牛奶被老鼠喝過後下回合會自己恢復不合理。牛奶被老鼠喝過後就停止升級了。
2. 列車開放到離島後又載人開到離島，動畫分兩段有點多餘，此外離島的升級也不夠驚豔（目前只有多一根風力發電）。
3. 後期動畫還是偏長，你看能不能合併某些表現或刪減。」

追問後的決定：咬住到老鼠搭上捷運為止；風車島＝三支風機＋燈塔光束、不搭車，而且「畫面不要一直閃，像停電後的燈泡閃現過於快速也是要修的點」；後期只修劇本（◆ 上限 8 → 6 s、一般 4.5 → 3.5 s），不加速。

本批接在 `2026-10-31-single-path-design.md` §8 R37 之後，記成 R38–R41。

## 目標／非目標

- 目標：四件事各自獨立可驗收；規則只動一條（R38），其餘純演出；所有關卡照舊（1 解、節奏無 ⚠、截圖預算）。
- 非目標：不加速回合、不改物品等級表、不動其他物品的假升級、不改終局。

## R38 老鼠咬過的牛奶停止升級（規則）

現況：老鼠放下時牛奶 ≤2 → `rat.fx` 的 `delta −1`；下回合 `milk.up[2]` 是 `auto`，立刻長回來（使用者：「下回合會自己恢復不合理」）。
另一條既有規則（計畫 14 R30 `bite`）：老鼠 Lv1–2 在島上時**放下**的牛奶／珍奶立 `bitten_<id>` 旗標，老鼠搭上捷運（Lv3）之前不長（`engine.heldBy`）。

改法：同一條 fx 同時咬住——規則資料 `rat.fx[0]` 加 `bite: true`；引擎 `actionEvent` 看到 `a.bite` 且這條有 `delta` 就立 `bitten_<target> = cause`（事件帶 `flag: { name, value }`，演出層照舊折旗標）。之後的升級檢查走既有 `heldBy`：老鼠還在 `bite.while`（Lv1–2）就擋著，Lv3 一到就放行。不另加新機制、不加新文字（最小文字原則）。

影響：只會多擋、不會多放——唯一正解（老鼠最後放、牛奶早已滿級）不變，全枚舉仍須剛好一解（`npm run check`）；壞結局分佈會往「鮮奶過期」偏。`test/helpers/endings.js` 的 `EXAMPLE` 代表順序若結局改變，換成仍是該結局的順序（`npm run solutions` 重產 solutions.md 可查）。

演出：老鼠放下的劇本已經演 LEVEL DOWN；被咬住的牛奶之後每回合進 `wait`（`for: ['rat']`），老鼠指標照 §5.2 站在它門口——玩家看得到「因為老鼠」。不加泡泡字。

## R39 電燈 Lv7：不搭車，風車島變成風電場（演出）

現況：代幣 Lv7「捷運通車到離島」已經開一趟列車去風車島（8.2 s）；電燈 Lv7 電工再搭一趟去按開關（7.4 s），島上只多一根風機。

改法：
- 電燈 Lv7 劇本不再搭車（`enter`／`board`／`ride` 那條線整個拿掉，含 `trainLikely` 分支與鋪支線 `lay`）。電工照計畫 16 從 Lv7 起住在島上（`bulb.electrician` 名冊宣告不變），零件出現時他就在島上。
- 畫面（◆，整段含鏡頭 4.5–6 s）：鏡頭飛到風車島（`WIND`，`ISLAND_ZOOM`）→ 第二、第三支塔身與電池屋閃白立起 → 三個轉子從靜止轉起來（1.2 s 慢慢加速到通電速度，不是一換就滿速）→ 燈塔頂燈與光束同一拍亮起、守塔人出現 → LEVEL UP（電燈格）→ 回全景。不閃、不急：每一拍之間有停頓。
- 零件：第三支風機（塔身在 `sat.windmill.stage1`，轉子是 `sat.windmill` 的第二個 twin：`twins: [TWIN, TWIN2]`，縮 0.7）；位置由實作者定在島的東北側、不壓到電工的 wander 環、開關箱、電池屋（既有測試 651 的淨空）。轉子加速：`blades` 零件 `userData.spinUp(dur)`——建好（預熱）時靜止，劇本那拍呼叫才從 0 加速到 `speed`；跳過／瞬間演完就是滿速。
- 風車島支線（`token.spur.windmill`）只跟代幣 Lv7 走：`token.js` view 不再因 `lv.bulb ≥ 7` 鋪支線（電燈不搭車了，支線不該因電燈出現）。代幣 Lv7 的「風車島支線已被電燈鋪好」分支變成死碼，一併拿掉。
- 既有的「沒有列車」後備分支（淹水局等）不再需要：所有局都走同一條劇本。

## R40 停電的燈：緩緩呼吸，不閃（演出）

現況（R37）：每 4.5 s 急閃兩下（0.12 s 亮），使用者：「閃現過於快速」。

改法：`flickerOn(t, seed)` → `flickerLevel(t, seed)` ∈ [0, 1]：每 `FLICKER_PERIOD` 7 s 一次，0.5 s 緩緩亮到 1、0.7 s 緩緩暗回 0（smoothstep），各站錯開 seed × 1.3 s；其餘時間 0。`flicker` 零件每幀把亮的那份的 `emissiveIntensity` 設成 `FLICKER_GLOW × level`、`visible = level > 0`（亮的材質本來就在登記表外、自己管強度）。任何時刻最多一兩站在呼吸。

## R41 後期劇本修剪（演出）

上限：`SCRIPT_MAX` 4.5 → 3.5 s、`KEY_MAX` 8 → 6 s（`test/helpers/show.js`，pace 共用）。例外表 `SCRIPT_EXCEPT`：`bulb 2`（環掃）6 → 4.5；`baseball 1`、`token 1`、`token 2` 6 → 4.5。
原則：留主意（走到、按下、閃白出現、LEVEL UP），砍的是停頓與重複鏡頭——縮 `wait`／`hold`、走路加速、把能同時演的拍疊進 `together`、同一格的連續事件不重複平移。不砍 LEVEL UP、不砍因果動作本身。
超過上限的劇本清單與每一條的具體刪法在實作計畫（由 `npm run pace -- --verbose` 量出：一般 18 段、◆ 5 段；電燈 Lv7 改由 R39 重寫）。pace 的回合上限不變（60 + 8 × (◆ − 1)），目標是正解第 8 回合 48.8 s、最後一輪 45.4 s 各省 8–10 s。
