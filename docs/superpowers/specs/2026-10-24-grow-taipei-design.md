作者：使用者（概念、規則方向、物品、結局）＋ Claude（整理與補足；標記「我的決定」處為 Claude 代為決定，使用者可推翻）

## 1. 這是什麼

一款致敬 Eyezmaze「GROW」系列（特別是 GROW Island）的網頁解謎小遊戲，舞台是一座 low poly 的台北島。畫面下方有 8 個「城市發展物品」，玩家一次放一個，每放一個，島上所有東西會依規則連鎖成長。放的順序決定島長成什麼樣。8 個都放完後，全島接受最終考驗（對岸試射飛彈），然後進入結局。

美術借鑑「台北順起來 HEART 政策島」（puma.taipei/heart-island）的 low poly 島嶼語言：藍綠色海、奶油與珊瑚色、平面著色、六角形島、白色邊框、黑髮彩衣小人。只借風格，不借程式、不借模型、不涉及任何候選人或政黨。

物品刻意選「生活化但有時事梗」的東西（鮮奶、晶片、老鼠……），致敬政策島「一格政見」的概念，但內容是城市小品與惡搞，不是政見。

### 1.1 為什麼做

- 使用者想做一個可以在社群上分享的台北主題小遊戲，搭上 2026 秋天台北的話題（輝達總部、安鼠之亂、飛天車預購、颱風）。
- 使用者已有一套 GROW 式規則引擎與求解器原型（`grow_prototype/`），這次是把它換上台北主題並升級成 3D。

### 1.2 成功長什麼樣

- 一個人在手機上打開連結，30 秒內懂怎麼玩，第一局就看到至少一個好笑的壞結局，截圖分享。
- 老玩家會為了看兩個真結局反覆嘗試（GROW 系列的核心樂趣）。
- 整體觀感被認出「這是 GROW 致敬」也被認出「這是台北」。

## 2. 目標、非目標、反目標

**目標**
- 忠實的 GROW 手感：放一個東西 → 連鎖反應一個一個演 → 等級指示 → 全部 MAX 才是真結局。
- 兩個真結局（賽博龐克台北／外星人統治台北）＋ 一組值得特地去解鎖的壞結局，每個都有截圖點。
- 純靜態網頁，手機直式與桌機都能玩，載入在 4G 下 10 秒內可玩。
- 規則由求解器驗證：**剛好兩條**順序能全滿，且分別通往兩個真結局。

**非目標**
- 多語言（只做繁體中文，用台灣用語）。
- 帳號、排行榜、後端。
- 真實政見內容、候選人、政黨符號。
- 手工建模或外包美術；全部程式造型＋ CC0 模型。
- 完整音效設計（最多幾個合成音效，預設可關）。

**反目標（做到也算失敗）**
- 畫面讓人覺得在幫某方拉票、或影射真人。
- 飛彈橋段演得沉重或恐怖。整個遊戲的語氣是「惡搞但溫柔」，飛彈被擋下要像放煙火，沒擋下要像卡通被撞扁。
- 「連鎖升級」演成一次全島同時跳級。GROW 的爽感來自一個接一個、有因果地演。
- 3D 太重以致手機跑不動或載入太久。

## 3. 限制

- 技術：three.js，ES module，無打包工具，瀏覽器直接開（開發時用本機靜態伺服器載入 GLB）。部署到 GitHub Pages。
- 美術：程式造型（kit 零件）＋ Kenney／Quaternius 的 CC0 模型。所有外部模型載入時轉成 flat Lambert 材質，色票統一（見 §9）。
- 授權：只用 CC0 素材，`assets/` 內附授權檔。不使用 Quaternius 新版「Quaternius Asset License」的包。
- 規則引擎沿用 `grow_prototype/` 的語意（條件式、放置反應、卡住規則），升級成連鎖版（§6）。
- 不接任何追蹤或分析（連 GA 都不要）。
- 檔案大小：首次載入的 JS＋模型＋貼圖總量以 6 MB 為上限（我的決定）。

## 4. 玩法

### 4.1 一局的流程

1. 開場：空島，中央是 101 工地，北側台地上是陽明山（冒小油坑的煙）和北投溫泉池。下方 8 個物品框。
2. 玩家點一個物品框 → 物品從框裡飛到島上定位 → 開始演連鎖反應（§6、§7）。
3. 演完，框上出現「Lv.n」。重複到 8 個都放完。
4. 最終考驗：飛彈（§8.1）。
5. 結局（§8）。結局畫面上有：結局標題卡、8 個物品的最終等級（MAX 會標黃）、「再玩一次」「分享」「結局圖鑑」。

每個物品只能放一次。沒有悔棋。隨時可 RESET。

### 4.2 畫面與操作

- 視角：固定的 3/4 俯視，可用拖曳微轉（±30°）與滾輪／雙指縮放。演出時鏡頭會自動對焦正在變化的角色，演完回到全景。
- 手機直式：島置中偏上，物品列固定在底部兩排 4 個。桌機：一排 8 個。
- 點擊畫面可跳過目前演出（直接跳到該回合結束狀態），不能跳過結局前 2 秒的標題卡。
- 右上角：RESET、怎麼玩、結局圖鑑、音效開關。
- 怎麼玩：一張卡，三句話：「一次放一個」「順序會改變結果」「全部 MAX 看真結局」。

### 4.3 等級指示

照 GROW：每個物品框下方顯示「Lv.1」…「Lv.MAX」。只顯示目前等級，不解釋為什麼。這是玩家唯一的回饋，也是解謎的線索。

### 5.1 每個物品的等級與衍生角色

GROW 的關鍵（使用者觀察）：**物品升級時，不只物品本身變形，它衍生出來的角色也會升級，而且衍生角色可以被其他物品影響。** 所以下表每一級都寫「本體」與「衍生」。

**鮮奶（max 4）**
- Lv1：島西側出現牛奶箱。
- Lv2：牛奶箱旁長出小學（米色校舍＋操場），**衍生：3 個小孩**跑出來在操場繞圈。
- Lv3：校舍加一層；小孩**長高**（整個模型放大 1.3 倍，字面意義的「喝鮮奶長高」）。
- Lv4：校舍變成有鐘塔的學校；小孩戴上棒球帽（若棒球 ≥2 則組成少棒隊，會去球場）。
- 被影響：老鼠出現且 ≥2 → 小孩尖叫逃回校舍；颱風 Lv2 → 放颱風假，小孩在家（校舍窗戶亮）。

**晶片（max 5）**
- Lv1：島東側出現工地（圍籬、三角錐、一台吊車）。
- Lv2：廠房（無窗長方盒、煙囪冒白煙）。**衍生：2 個工程師**（白襯衫）從廠房走到 101 來回。
- Lv3：北士科園區（三棟玻璃盒＋園區招牌）；工程師變 4 個，改騎 YouBike。
- Lv4：「星群」總部（弧形玻璃建築）；101 頂端長出矽盾天線（環狀）。
- Lv5：矽盾待命，101 外圈每 3 秒閃一圈淡藍光。
- 被影響：老鼠 ≥2 且晶片 ≥3 → 工程師之一變成「鼠類偵防師」（拿放大鏡）開始追老鼠。

**燈泡（max 4）**
- Lv1：主路旁一盞路燈。
- Lv2：整條路都有路燈；**衍生：夜市攤 2 攤**在路尾出現（若珍奶已放，珍奶攤搬到夜市）。
- Lv3：路燈變霓虹招牌色；島進入「傍晚」色調。
- Lv4：全島 LED，101 做燈光秀（需晶片 ≥3 才能升到 Lv4）。
- 被影響：颱風 Lv2 時燈泡 <3 → **大停電**：所有燈熄、燈泡鎖死（之後永遠不升），鮮奶 −1（冰箱壞了）。

**代幣（max 4）**
- Lv1：捷運站（藍色圓頂小站＋代幣機）。
- Lv2：軌道環繞主島；**衍生：一列 3 節列車**開始繞圈。
- Lv3：環狀線延伸，架橋連到 2 座衛星島（燈塔島、遊樂場島）；列車變 5 節。
- Lv4：無人駕駛霓虹列車（需晶片 ≥3）。
- 被影響：颱風 Lv2 時代幣 <3 → **捷運淹水**：站體變游泳池，列車停駛，小人在裡面划船；代幣鎖死。老鼠 ≥3 且代幣 ≥2 → 老鼠搭捷運（列車車頂坐一排老鼠）。

**颱風（max 3）**
- Lv1：島上空一朵灰雲，開始下毛毛雨。放下的同一回合不做檢查。
- Lv2：暴風圈。**全島檢查**（§6.3）。所有小人跑回室內；若珍奶已放 → 珍奶 +1（颱風天叫外送，一台外送機車在雨中亂竄）。
- Lv3：風停，彩虹。**災後重建**：所有房子升一個外觀級（屋頂換新色），河濱公園出現。
- 颱風的升級條件設計成「它會自己走完」（Lv1→Lv2→Lv3 各需一回合），所以放的時機就是考驗的時機。

**老鼠（max 4）**
- Lv1：一隻老鼠在棒球場位置附近晃。
- Lv2：一窩（5 隻），開始咬東西：若鮮奶已放 → 鮮奶 −1；若珍奶已放 → 珍奶攤翻倒一回合。
- Lv3：老鼠搭捷運（需代幣 ≥2）或老鼠泡溫泉（需代幣 <2）。
- Lv4 **分岔**：
  - 晶片 ≥3 時升到 Lv4 → 被鼠類偵防師收編，變成「機器鼠」吉祥物（銀色、有天線），跟在偵防師後面排隊。→ 賽博龐克路線。
  - 晶片 <3 時升到 Lv4 → 泡了北投溫泉的老鼠**變異**：長大兩倍、三隻眼、會發綠光，開始對天空揮手。→ 外星人路線。
- 被影響：颱風 Lv2 且老鼠 ≥2 且棒球 ≥2 → 老鼠被大水沖進大巨蛋 → **大巨蛋鼠災**。

**珍奶（max 3）**
- Lv1：路邊珍奶攤車。
- Lv2：排隊人龍（6 個觀光客，拿相機）。
- Lv3：珍奶噴泉（攤車變成圓形小廣場，中央一杯巨大珍奶）。若鮮奶 ≥2 → 招牌變「鮮奶珍奶」，排隊變 10 人。
- 被影響：颱風 Lv2 → +1（外送）；老鼠 Lv2 → 攤車翻倒一回合（不降級，純演出）。

**棒球（max 4）**
- Lv1：沙地球場。
- Lv2：大巨蛋（白色扁橢圓頂）。**衍生：2 個球員**在門口傳接球。
- Lv3：比賽開打（需代幣 ≥2 載觀眾）；巨蛋頂開一條縫透光，加油聲。
- Lv4：演唱會（需燈泡 ≥3）；巨蛋外圍打光，某天團的藍色應援棒（不用真名）。
- 被影響：老鼠被颱風沖進來 → 比賽暫停，兩個工作人員拿水桶追老鼠（大巨蛋鼠災壞結局的畫面）。

### 5.2 101（非物品的中央地標）

101 不是物品，它反映全島進度：`總等級 = 所有物品等級總和`。
- 0–6：工地（吊車會動）。
- 7–14：半成品，建到一半。
- 15–22：完工。
- 23+：點燈。
- 晶片 Lv4 起長出矽盾天線；結局時變成對應型態（§8）。

### 5.3 衛星島與背景

- 7 座衛星島（燈塔、風車、石堆、階梯丘、遊樂場、小森林、寶箱島）。代幣 Lv3 會架橋連到其中兩座；外星人結局會把石堆島變成降落場。
- 背景整片 low poly 山坡＋上千棵 instancing 的小樹＋幾間小屋（陽明山）。遠處霧化。
- 海上 3–4 艘小船繞圈，純裝飾。

## 6. 規則引擎（連鎖版）

### 6.1 狀態

`state[i]` = 物品 i 的等級，0 表示未放。另有少量旗標（`blackout`, `flooded`, `ratBranch: null|'cyber'|'alien'`, `domeRats`），全部可由等級向量加放置順序推導，但為了演出方便明確記錄。

### 6.2 一回合

```
place(X):
  state[X] = 1
  events += [placed X]
  Phase A 放置反應：X.fx 依序套用（可加可減，夾在 [1,max]），每個套用記一個事件
  Phase B 連鎖：
    repeat:
      changed = false
      for i in 物品順序（固定：鮮奶,晶片,燈泡,代幣,颱風,老鼠,珍奶,棒球）:
        if state[i]==0 or state[i]>=max[i] or locked[i]: continue
        if 某 stall 規則命中 i: 記一個 stall 事件（每回合每物品最多一次）; continue
        if tick[i](state) 成立: state[i]++; 記一個 grow 事件; changed = true
        （升級可能觸發 onLevel 反應，例如颱風 Lv2 的全島檢查，立刻套用並記事件）
    until not changed
```

- 與原型的差別：原型一回合每物品最多 +1；這裡是**反覆掃描到不動為止**，所以一回合可以連升多級、也可以 A 升了讓 B 升。這就是「放一個東西，劈哩啪啦連升」。
- 保證終止：每次迴圈至少有一個等級 +1，等級有上限；減級只發生在 Phase A 與 onLevel 反應且每回合有限次（建造者需在 engine 加一個安全上限，例如 64 次掃描，超過就 throw）。
- 事件列表是有序的，演出層照順序演（§7）。

### 6.3 颱風 Lv2 的全島檢查（onLevel）

依序：燈泡檢查 → 代幣檢查 → 老鼠檢查 → 鮮奶放假 → 珍奶外送。每一項各記一個事件。檢查結果可能設定 `locked[燈泡]`、`locked[代幣]`，這兩個鎖是壞結局的主因，也是「颱風要放對時間」的核心謎題。

### 6.4 條件語言

沿用原型：`always / present / absent / minLevel[id,n] / maxLevel[id,n] / ltPlus[a,b,k] / and / or`，新增 `age[id,n]`（id 放下後已經過 n 回合，用於颱風逐回合推進與鮮奶過期）與 `flag[name]`。`maxLevel` 採 solver4 的絕對語意（未放置的 0 也算 <n）。所有規則寫在 `rules/spec.js` 單一檔案，純資料，引擎與求解器共用。

### 6.5 求解器要驗證的事

8! = 40,320 種順序，Node 幾秒內跑完。`npm run check` 必須通過：

1. **剛好 2 種**順序讓 8 個物品全滿。
2. 其中一種的 `ratBranch` 是 `cyber` → 結局 A；另一種是 `alien` → 結局 B（判定看旗標，不看放置順序；見 §8.2）。
3. 每個壞結局（§8.3）的**條件**至少在 1 種順序裡成立，且「晶片未 MAX 到終局」在至少 30% 的順序裡成立（以條件成立計，不以標題卡計）。
4. 難度指標：隨機順序的平均 MAX 數 ≤ 3；貪婪策略（每步選能讓總等級升最多的物品）不能到達真結局。
5. 沒有任何順序讓引擎超過掃描上限。

規則數值（哪一級需要誰幾級）由建造者用求解器調到滿足上述；§5.1 的條件是起點，不是定案。原型裡的 `solver4_auto_tighten.js` 要改成「目標是剛好 2 解且滿足條件 2」。

## 7. 演出層（角色與導演）

### 7.1 角色（Actor）

- 每個角色是一個 three.js Group，有 `id`、`owner`（哪個物品生的）、`state`（目前外觀鍵）、`pos`、`path`（可選）。
- `actors/<item>.js` 定義該物品的本體與衍生角色，以及對事件的反應：`onEvent(event, world) → [transition]`。例如代幣的列車對 `grow(晶片,3)` 回應「換成霓虹車廂」。
- 轉場用的是「彈跳＋煙霧」的 GROW 式變身：舊模型縮到 0，煙霧冒出，新模型從 0 彈出（easeOutBack），0.6 秒。移動用 catmull-rom 路徑。
- 角色的外觀只由 `state` 決定，`state` 是純函數 `f(等級向量, 旗標)`。這讓「跳過演出」只要重算所有角色的 state 並直接套用。

### 7.2 導演（Director）

- 輸入一回合的事件列表，照順序演；每個事件 0.5–1.2 秒；同一事件涉及多個角色時同時動。
- 鏡頭：每個事件把鏡頭目標平滑移到事件主角，演完回全景。連續事件在同一區域時不來回移動鏡頭。
- 文字：每個事件在主角頭上冒一個白色圓角氣泡，一句台味短句（例：「老鼠搭捷運了啦」「颱風假！珍奶外送爆單」）。字句寫在 `rules/spec.js` 的事件 `story` 欄位，和原型一樣。
- 點畫面跳過：導演立即把剩餘事件的最終 state 套到所有角色（§7.1），鏡頭回全景。

### 7.3 小人

- puma 風：膠囊身、球頭、黑髮帽、彩色上衣、深色褲，走路時手腳擺動。不是 GROW 的黃色小人（使用者看過兩版後選 puma 風）。
- 基本島民 6 個沿主路來回走；衍生小人（小孩、工程師、觀光客、球員、偵防師）由物品生成。
- 動物與生物用 Quaternius 動畫模型：老鼠（Walk/Run/Idle/Jump）、外星生物（Flying_Idle）、柴犬（純裝飾，一隻）。

## 8. 結局

### 8.1 最終考驗：飛彈（第 8 個物品放完後必演）

第 8 個物品的連鎖演完 → 鏡頭拉遠 → 海平面彼端一道火光 → 一枚卡通飛彈（紅白條紋、圓頭）劃過天空朝 101 飛來。

- 晶片 = MAX：101 矽盾張開（半透明藍色圓頂），飛彈撞上去碎成煙火，島民全部抬頭歡呼。→ 進入真結局或一般壞結局判定。
- 晶片 < MAX 且颱風正好在 Lv2（暴風圈中）：飛彈被颱風吹歪，掉進北投溫泉，溫泉變成「飛彈溫泉」（溫泉池裡插著一枚沒爆的飛彈，老鼠在上面泡）。→ 壞結局「颱風擋飛彈」。
- 晶片 < MAX 其他情況：飛彈命中 101，101 像吸管一樣彎成 L 形，所有小人躺平比讚。→ 壞結局「矽盾未就緒」。

語氣：全程卡通，飛彈有表情（會皺眉），沒有火、血、廢墟。

### 8.2 真結局（兩個，都需 8 個全 MAX）

判定：8 個全 MAX → 一定是真結局，不受任何壞結局旗標影響（我的決定）。A 或 B 看 `ratBranch`：老鼠升到 Lv4 的那一刻晶片 ≥3 → `cyber`；否則 `alien`。求解器負責保證兩條正解各走一邊。

**A. 賽博龐克台北**（`ratBranch = cyber`）
矽盾擋彈後：天空快轉到夜晚 → 全島霓虹 → 捷運列車發光 → 101 變成頂端有巨型螢幕的黑色高塔 → 一台紅色飛天跑車（不是任何真實品牌，但明眼人看得出來）從海上飛進來繞 101 一圈停在屋頂 → 螢幕跑馬燈：「飛天跑車今日抵台，先付清 755 萬」 → 機器鼠在屋頂排隊迎接 → 標題「CONGRATULATIONS!! 賽博龐克台北」。

**B. 外星人統治台北**（`ratBranch = alien`）
矽盾擋彈後（或 UFO 直接把飛彈吃掉，建造者擇一，吃掉比較好笑）：變異老鼠對天揮手 → 石堆島變成降落場 → 三台 UFO 降落 → 外星生物（綠色、會飄）下船 → 101 變成母艦（頂端變成倒扣的碟型，底座懸浮離地 1 公尺）→ 所有島民換成三眼版本、動作不變繼續排隊買珍奶 → 變異老鼠坐在 101 頂端戴王冠 → 標題「CONGRATULATIONS!! 外星人統治台北」。

### 8.3 壞結局（有標題卡的）

| 標題 | 條件 | 畫面 |
|---|---|---|
| 大停電 | 颱風 Lv2 時燈泡 <3 | 全島黑，只剩 101 一盞紅燈閃；小人舉手機照明 |
| 捷運淹水 | 颱風 Lv2 時代幣 <3 | 車站變游泳池，小人划船，列車泡在水裡 |
| 大巨蛋鼠災 | 颱風 Lv2 時老鼠 ≥2 且棒球 ≥2 | 比賽暫停，工作人員拿水桶追老鼠 |
| 矽盾未就緒 | 最終考驗晶片 <MAX | 101 彎成 L，小人躺平比讚 |
| 颱風擋飛彈 | 最終考驗晶片 <MAX 且颱風 Lv2 | 飛彈插在溫泉裡，老鼠泡在旁邊 |
| 鮮奶過期 | 旗標：鮮奶放下後連續 4 回合停在 Lv1（之後升滿也不清除） | 整島泛黃，小人捏鼻子，牛奶箱長腳跑掉 |
| 珍奶糖分超標 | 旗標：珍奶升到 MAX 的那一刻鮮奶 <2 | 所有小人圓成一顆球滾來滾去 |
| 再接再厲 | 其他未全 MAX | 一般畫面＋等級列，沒有標題卡 |

判定規則（我的決定）：
- 先看是否全 MAX → 是就進真結局（§8.2），壞結局旗標只在結局畫面的等級列旁用小字註記（例：「順便：鮮奶過期」）。
- 否則以表中順序取第一個成立的當標題卡。前三個是颱風檢查當下的鎖定事件，矽盾未就緒／颱風擋飛彈是終局事件，後兩個是旗標。
- 畫面上所有成立的效果都要呈現（停電又淹水就是黑掉的游泳池）。
- 鎖定類（停電、淹水）天然排除全 MAX；旗標類不排除，所以求解器不需要把它們當成正解的額外約束。

### 8.4 結局圖鑑

10 格（2 真 + 7 壞 + 再接再厲）。達成過的亮起並顯示標題；沒達成的顯示「？？？」。存 localStorage。這是重玩動機。

點亮規則（我的決定）：一局結束時，所有**條件成立**的壞結局都點亮，不只標題卡那一格；真結局只在真的走到時點亮。所以玩家不需要刻意製造「只停電不淹水」的局面。

### 8.5 分享

結局畫面「分享」按鈕：
- 把目前 3D 畫面加上標題卡、8 個等級、網址，合成 1200×630 PNG。
- 手機有 Web Share API 就用它；否則下載 PNG 並複製一段文字（「我在《台北成長》走到了【大巨蛋鼠災】，你能全部 MAX 嗎？」＋網址）。
- 頁面有 OG tags 與一張預設分享圖。

## 9. 美術方向

### 9.1 色票（來自試作 v2/v3，已驗證）

海 `#4fa6b4`、奶油 `#fff8f4`、沙 `#e9dcc6`、珊瑚 `#db6a41`、墨 `#211d1d`、黃 `#fcea8b`、草 `#bfd39c`、草地 `#cfe0a8`、岩壁 `#d2b48c`、樹三色 `#9bbd7e / #8aaf70 / #6f9560`、牆 `#f1e7da`、窗 `#5c5650`、玻璃 `#9cc3bf`、山 `#b3c79a`、膚 `#f3c9a5`、髮 `#3a2a22`。
上衣 8 色：珊瑚、藍 `#5a88b2`、粉 `#f2b5c6`、綠 `#8db86f`、黃、白、深藍 `#3f5a8a`、橘黃 `#e8b04a`。
賽博龐克結局另加霓虹粉 `#ff3fa0`、霓虹藍 `#3fe0ff`。外星人結局另加紫地 `#b9a7d6`、外星綠 `#5fcf7a`。

### 9.2 光線與材質

- 全部 `MeshLambertMaterial` + `flatShading`，含外部模型（載入時轉換，貼圖與頂點色保留）。
- 一盞方向光（有陰影，PCFSoft，2048 map，bias −0.0006）＋ 一盞半球光。白天／傍晚／夜晚三組參數（試作 v2 已有），燈泡等級會推動時段。
- 霧：`Fog(天空色, 45, 130)`。
- 色調映射 ACES，曝光 1.05。
- 不用後處理（無 bloom、無 SSAO），效能優先。發光靠 emissive。

### 9.3 幾何語言

- 島：軟化的六角形（每邊 4 段、角落圓化 0.15、半徑抖動 3%），側面向內收 0.86，頂面白色環形邊框，水下一圈半透明沙色淺灘。
- 建築：方塊＋深色直條窗＋橘色平頂；尖頂用四角錐；屋頂色只用珊瑚、深藍、黃三種。
- 樹：Kenney Nature Kit 的樹（`tree_default/oak/detailed/fat/small`），葉色改成樹三色；背景山坡用程式圓錐 instancing。
- 101：四角錐台堆疊 8 節，每節上緣一圈 emissive 白邊，頂端尖塔。工地期有黃色吊車。
- 整體密度目標：主島上至少 80 個可見物件（含填充的花草石頭）。試作 v3 已達 60。

### 9.4 模型來源（全 CC0）

- Kenney：Nature Kit、City Kit Suburban、City Kit Commercial（城市包需附 `Textures/colormap.png`）。
- Quaternius（經 `trebeljahr/quaternius-showcase` 鏡像，該鏡像只收 CC0 包）：nature、buildings_pack_3、cyberpunk、easy_enemies（老鼠）、ultimate_space（外星生物、圓頂）、spaceships（UFO 用 `Pancake`）、ships（小船）、animals（柴犬）、modular_men（備用）。
- 專案 `assets/` 只放實際用到的檔案，附 `LICENSES.md` 列出每個來源。試作 v3 的 `spike/assets/` 有 75 MB 全集，正式專案要挑。
- 已知坑（試作學到）：Kenney 葉色是薄荷藍綠要染色；鏡像少了賽博龐克招牌的貼圖，招牌面直接塗霓虹色＋emissive；有骨架的模型取尺寸前要 `skeleton.update()` 與 `computeBoundingBox()`，否則縮到看不見；Quaternius 的 `-transformed` 檔是 Draco 壓縮，要掛 DRACOLoader。

### 9.5 UI

- 字體：Noto Sans TC（系統有就用，沒有就退到系統中文字型，不另外載入 webfont，我的決定）。
- 物品框：白底、圓角 12、內嵌 1.5px 淡邊、下方珊瑚色「Lv.n」小標。已放的框變淡並顯示等級。
- 標籤氣泡：白底圓角藥丸、珊瑚色編號、黑字。
- 標題卡：奶油底、珊瑚色大字、墨色描述一句。
- Logo：「GROW TAIPEI」珊瑚色粗體兩行 + 「台北成長」。

## 10. 技術架構

```
grow_taipei/
  index.html            單頁，importmap 指向 vendor/
  vendor/three/         three.js r170 的 build 與用到的 addons（本地化，不靠 CDN，我的決定）
  src/
    rules/spec.js       8 個物品、條件、放置反應、卡住、onLevel、story 文字（純資料）
    rules/engine.js     連鎖引擎：place(state, X) → {state, events}；Node 與瀏覽器共用
    rules/endings.js    結局判定：state + 順序 → 結局 id
    solver/run.js       全排列、統計、檢查（npm run check）
    solver/tighten.js   自動收緊到「剛好 2 解」
    scene/kit.js        程式零件（方塊、圓角方塊、錐、多面體、樹葉團…）＋ instancing 批次
    scene/island.js     島、台地、衛星島、背景山、海、泡沫
    scene/assets.js     GLB 載入、材質轉換、尺寸正規化、動畫
    scene/people.js     小人生成與走路
    actors/<item>.js    8 個物品的本體與衍生角色
    actors/tower.js     101
    director.js         事件 → 轉場 → 鏡頭
    endings/*.js        飛彈、A、B、壞結局演出
    ui/                 物品列、卡片、圖鑑、分享
    main.js
  assets/               精選 GLB + 貼圖 + LICENSES.md
  test/                 node:test：引擎語意、求解器檢查、結局判定
  docs/superpowers/specs/  本文件
  spike/                丟棄式試作（保留 html 供參考；assets/ 不進 git）
  grow_prototype/       舊原型（保留，引擎語意的參考）
```

- 無建置步驟。`npm run check` 跑求解器；`npm test` 跑 node:test；`npm run shot` 用 headless Chromium 截 6 張固定畫面（開場、第 4 回合、颱風、飛彈、結局 A、結局 B）放到 `shots/` 供肉眼比對。
- 效能目標：中階手機 30 fps；主島 draw call ≤ 150（靠 kit instancing）；骨架動畫角色同時 ≤ 12 個。
- 品質分級：`?quality=low` 關陰影、減背景樹；偵測 `innerWidth ≤ 800` 或行動裝置 UA 自動用 medium（陰影 1024）。
- 狀態持久：只有結局圖鑑與音效開關進 localStorage。
