# 同物品連著演、零件一起長、回合預熱、LEVEL UP 冒在變的零件上 實作計畫（計畫 15）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 使用者 2026-11-02 看錄影（`螢幕錄製 2026-11-02 214949.mp4`）：「學校先跳 level up、跑其他物品、最後又回來跳學校第二段」「鐘塔和校舍分離」「升級動畫卡頓」。查明：(1) 引擎每回合每物品只升一次，使用者看到的「第二段」是**燈泡**的 LEVEL UP 冒在學校上方（燈泡錨點、變電所都貼著學校那一側；◆ 全景打字也落在學校正上方），另外**剛放下的物品**真的分兩段（放下 → 其他物品 → 它的 Lv2）；(2) `beats.apply` 同一拍的零件鍵預設錯開 0.15 s（校舍、鐘塔、校門一個接一個長）；(3) 建築出現那一刻才下載模型、合併烘焙、編譯 shader。使用者裁定：A、B、C、D 全做，D 不加小字，**畫面上的字越少越好**——「恭喜畢業」「世界珍奶節」也拿掉。

**Architecture:** 全在演出層與舞台，規則層不動。A：`src/show/turn.js` 建拍前把剛放下物品的成長事件搬到它的放下事件後面（純函數、看 `via` 不破壞因果）。B：`src/show/beats.js` 的 `apply` 預設 `stagger` 改 0。C：`src/actors/stage.js` 新增 `prepare(events)`——回合開始先把整回合會出現的零件建好藏著（含 glb 模型先載），`show.turn` 開頭呼叫，再透過 ctx 的 `compile` 鉤子讓 `app.js` 用 `renderer.compileAsync` 先編譯材質。D：LEVEL UP 冒在**這個事件真的變了的零件**上方（舞台記每個事件套到的鍵），兩處標題字拿掉。

**Tech Stack:** 原生 ES modules、three.js r170（vendor）、`node --test`、無頭演出 `test/helpers/show.js`（真 THREE、假 assets）、`npm run pace`、`npm run shot`。

**Spec:** 本檔 §設計；上位設計 `docs/superpowers/specs/2026-10-31-single-path-design.md`（§6 演出、§8 裁決延續到 R32）。

## 設計（決定好的事）

1. **A 剛放下的物品連著演**（`turn.js` 新純函數 `groupPlaced(events)`，`buildTurn` 一開頭呼叫）：
   - 找 `placed` 事件（index p，物品 id）。「頭段」= p 以及緊接在後、連續的 `e.item === id || e.cause === id` 的事件（颱風放下的 fx、雨中被鎖的 fx、被咬的 fx、老鼠咬鮮奶 −1）。
   - 「成長段」= 頭段之後第一個 `kind === 'grow' && item === id` 的事件，加上緊接其後、連續的 `e.item === id || e.cause === id` 的事件（跳級第二個 grow、onLevel 的 fx）。
   - 把成長段整段搬到頭段正後面，**除非**成長段裡任一 grow 的 `via` 含有「夾在中間的事件」改過的物品（中間事件的 `item`、或 `delta.target`）——那就不搬（原樣回傳）。沒有 placed、沒有成長段、或成長段本來就緊接著頭段：原樣回傳（同一個陣列參照）。
   - 跳級合成（`jumpPairs`）在搬完之後算，不受影響。`foldEvent` 逐事件折 view 的順序跟著搬，`s.prev` 照新順序。
   - 測試（`test/turn.test.js`）：珍奶放下回合 `[P:boba, milk6>7, chip2>3, chip3>4J, bulb3>4, bulb4>5J, token5>6, boba1>2, baseball5>6]` → boba1>2 搬到 P:boba 後；颱風放下回合的 fx（cause typhoon）留在頭段、後面沒有颱風 grow 不動；老鼠放下 `[P:rat, fx(cause rat, item milk, delta), milk1>2, rat1>2(via ['milk'])]` → 不搬（via 含中間升過的鮮奶）；`[P:rat, fx(cause rat), rat1>2(via [])]` → 本來就相鄰、原參照；用真引擎跑唯一正解九回合，`buildTurn` 的 mark 順序裡每個 placed 的物品，它的第一個 grow 緊接在頭段後。
2. **B 零件一起長**：`beats.apply` 的預設 `stagger` 0.15 → 0（`STAGGER` 常數刪掉或設 0；`stagger` 參數保留，沒有人再傳非 0）。`tagAlong` 機制保留（還是跟第一個一起 commit，不再有「不多佔一格」的意義，註解改掉）。`dur` 變成 `keys.length ? BLINK : 0`。`test/beats.test.js` 相關斷言改掉；`src/actors/baseball.js:159`、`src/actors/satellites.js:98`、`turn.js` 檔頭講 stagger 的註解改掉。拍縮短後 `npm run pace -- --check` 可能有一級掉到 3 s 以下（目前貼近下限的：鮮奶 2 的 3.1、晶片 2 的 3.1、燈泡 5 的 3.5、棒球 7 的 3.1 等）——掉到 3 s 以下的那一級在它劇本裡補 `B.wait`（補在 LEVEL UP 前、建築長完之後），每級至少 3.0 s、◆ 不超過 8 s；各回合上限不變。
3. **C 回合預熱**（`stage.prepare(events)`）：
   - `stage.js` 的 `fold(e)` 改成純函數 `foldStage(state, e) → state`（state = `{ lv, flags, meta, waits, stale }`），`apply` 與 `prepare` 共用（`apply` 把結果寫回閉包變數）。
   - `prepare(events)`：從現在的 state 複製一份，逐事件 `foldStage`，每一步對每個模組算 `mod.view(lv, flags, meta)`，跟「上一步的預熱 view」（起點是現在的 `views`）比 `diffParts`，新出現／換掉的鍵（`kind !== 'roster'`）用 `factory.build` 建好、`object.visible = false`、加進 `partsGroup`，存進 `prebuilt: Map<key + '\n' + JSON.stringify(spec), { spec, part, fp }>`（同一個鍵同一個 spec 只建一次）。回 `{ parts: [...object3d], ready: Promise }`——`ready` 等所有 glb／campus 零件的模型載好（見下）。不改 `views`、`live`、`pending`。
   - `make(s, key)`：先查 `prebuilt`（鍵 + JSON）；命中就從 map 拿走、回它；沒有才建。`swap` 非 deferred 的路徑把 `fresh.part.object.visible = true`（預熱的零件是藏著的）。
   - `dropPrepared()`：把 `prebuilt` 裡還沒用到的全部 `drop`、清空。`show.turn` 的 `end`（照常演完、跳過、中止）、`stage.reset` 都呼叫。
   - glb／campus 零件（`parts.js` 的 glb builder 與 `milk.js` 的 campus builder）回傳的 part 多一個 `ready`：Promise，模型加進 group 時 resolve（載入失敗也 resolve）；其他 kind 沒有 `ready`（當作已就緒）。
   - `show/index.js` `turn()`：`buildTurn` 之前呼叫 `const prep = stage.prepare(events)`，然後 `prep.ready.then(() => ctx.compile?.(prep.parts))`（不等它，拍照常開始）。`createShow` 的 `parts` 參數多一個可選 `compile`（函數，收 object3d 陣列）；`ctx.compile = compile ?? null`。
   - `app.js`：傳 `compile: objects => { for (const o of objects) view.renderer.compileAsync(o, view.camera, scene).catch(() => {}); }`（three r170 的 `compileAsync(scene, camera, targetScene)`：第一個參數只是要編譯的物件（`traverse`，藏著也算），燈光、霧從 `targetScene` 拿）。沒有 `compileAsync` 就用 `compile`。`?auto` 瞬間套用時 prepare 也跑（無害）。
   - 測試（`test/stage.test.js`、`test/show.test.js`）：prepare 之後 `prebuilt` 有該回合所有新鍵、物件 `visible === false`、不在 `partKeys()`、`footprints()` 不含它們、`obstacles()` 不含它們；之後逐事件 apply 時 `factory.build` 不再被呼叫（計數）而零件就是預熱那一個（同一個 object）；回合結束沒用到的被 drop；`reset` 清掉；`compile` 鉤子在 `ready` 之後收到預熱的物件陣列；glb 零件的 `ready` 在假 assets 的 spawn resolve 後才 resolve。live 一整局（唯一正解＋三條壞結局）`gameInvariants` 乾淨、draw call 不變（`npm run shot`）。
4. **D LEVEL UP 冒在變的零件上**：
   - 舞台記 `touched: WeakMap<event, Set<key>>`：`apply(e, opts)` 把 `changed` 裡 `kind !== 'remove'`、非 tagAlong、spec kind 不是 `'roster'` 的鍵加進去（同一事件多次 `only` 套用會累加）。
   - 新增 `stage.headOfEvent(e, id)`：鍵 = `touched.get(e)` 裡以 `${id}.` 開頭的；每個鍵的頭 = spec 有 `labelY` 就 `(at.x, at.y + labelY, at.z)`，否則建零件時量的包圍盒（`make` 時 `setFromObject` 存進 entry.bounds；空的跳過）取 `(centre.x, max.y + 0.3, centre.z)`；全部鍵合起來：x、z 取平均、y 取最高。沒有鍵、或鍵的包圍盒合起來水平邊長 > `WIDE`（2.4，整島的霓虹、路燈）→ 退回 `headOf(id)`。
   - `beats.levelUp`：`resolveTarget` 不動；`levelUp.start` 裡 target 是物品 id 字串、且 `ctx.event` 的 `item`（或 `delta.target`）等於它時，head 用 `ctx.stage.headOfEvent(ctx.event, id)`，否則照舊 `headOf`。`twice`（跳級）兩個字樣同一個頭。
   - 兩處標題字拿掉：`milk.js` grow 9 的 `B.focus('home', { hold: 0.8 }), B.levelUp('tower', { text: '恭喜畢業' }), B.focus(MILK)` 三拍刪掉（小孩跳、帽子落下 → 布條閃白 → LEVEL UP；這級量到 < 3 s 就補 `B.wait`）；`boba.js` grow 6 的 `B.levelUp('tower', { text: '世界珍奶節' })` 刪掉（◆ 整段仍 ≥ 6 s、≤ 8 s，不夠就把全景定格 1.2 加回 1.5）。`bubbles.levelUp` 的 `text` 參數保留（LEVEL DOWN 用），專案裡不再有別的字。
   - 測試（`test/beats.test.js`、`test/stage.test.js`、`test/milk.test.js`、`test/boba.test.js`、`test/bulb.test.js`）：燈泡 Lv6 的 LEVEL UP `at` 在變電所（`SUBSTATION`）上方、不在第一盞路燈；鮮奶 Lv2 的在早餐店上方；跨島的（燈泡 Lv9 霓虹）退回 `headOf`；兩處標題字不再出現在 bubblesLog；`grep -rn "text: '" src/` 只剩 LEVEL UP／LEVEL DOWN。
