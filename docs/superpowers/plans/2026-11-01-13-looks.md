# 鮮奶不用工人、攤車與火山重畫、泡溫泉、飛彈警告 實作計畫（計畫 13）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 使用者 2026-11-01 的五句話：「牛奶工人移除，牛奶直接生出學校和學生，學生維持兩人即可」「第一階段的珍奶店太醜請重新設計」「溫泉區可以有人進去泡」「火山太醜請重新設計」「飛彈發射過來前的警告請優化呈現方式」。

**Architecture:** 鮮奶＝`src/actors/milk.js` 的 placed／Lv2／Lv3 劇本不再找島民，建築自己長、兩個小學生從校門外進場（`milk.kids` 不再 `from` 島民；`landmarks.islanderCount` 只扣代幣）；攤車＝`boba.js cartParts()` 重畫；溫泉＝`landmarks.js` 溫泉客站進池裡（站位在池子裡、y 壓低到水面）；火山＝`landmarks.js` 新 builder `volcano`（有稜角的低多邊形錐、頂點色分層、熔岩口與熔岩痕發光）；警告＝`finale.js` 101 頂上的紅色旋轉警示燈零件 `finale.beacon`＋全島先抬頭再蹲下護頭（`people.js` 新手勢 `duck`）＋鏡頭先到 101 頂再回全景。

**Tech Stack:** 原生 ES modules、three.js（vendor；`parts.js` 的 compound 會把零件合併成一個 mesh，`glow` 的另算）、`node --test`、無頭演出 `test/helpers/show.js`、`npm run shot`（draw call 預算）。

**Spec:** 本檔 §設計；上位設計 `docs/superpowers/specs/2026-10-31-single-path-design.md` §8（裁決延續 R27）。

## 設計（決定好的事）

1. **鮮奶不用工人**（部分撤回 R23 的鮮奶那一項）：
   - placed：牛奶箱長出來（`grow`）＋ ♪ 冒在箱子上方（`B.bubble('milk.crate', '♪')` 若 bubble 能對零件；不能就 `B.wait`），整級 3–4.5 s，沒有人走過來。
   - Lv2 早餐店：店面與桌子長出來 → LEVEL UP，沒有人揮鐵鎚；整級 ≥ 3 s（不夠就 `B.wait` 補）。
   - Lv3 小學：校舍長出來 → 兩個小學生從 `KID_ENTRIES` 一個接一個走進來（`B.apply(e, { hold: ['milk.kids'] })` ＋ `B.spawn` 兩次，間隔照舊的 `gather`）→ 在操場集合 → ♪ → 跳一下、LEVEL UP。`milk.kids`：`n: 2`，**拿掉 `from`／`pick`**；`KIDS = [0, 1]` 不變；`pupilSpot` 刪掉。
   - `landmarks.islanderCount = HOMES.length − (lv.token >= 2 ? 1 : 0)`（島民只被站長轉走一個）。
   - 測試：milk.test 的 placed／Lv2／Lv3 劇本沒有 walk／gesture 找島民、live 兩個小學生都是新進場的（不是原本的島民）、islanders 不少；landmarks.test islanderCount；roster.test 的 pick nearest 單元測試留著（代幣還在用）、milk 的 live 換裝測試刪掉。
2. **攤車重畫**（`boba.js cartParts()`，Lv1–2 與被吹走的 `blownCart` 共用）：目標像夜市的珍奶攤車——
   - 車身：奶油色箱體 0.7 × 0.5 × 0.42（`C.wall`），正面下半一條珊瑚色裙板（高 0.18），上緣一條木色檯面（`0x9c7a4e`，0.74 × 0.04 × 0.46，微微凸出）；
   - 遮雨棚：檯面上方 0.3 的斜面（`hip` 或平板，0.8 × 0.03 × 0.5）＋ 5 條交錯珊瑚／白的直條（各 0.16 寬的薄盒，貼在棚面上）；前緣垂一排小波浪（3 個小 `dome`）；
   - 招牌杯：棚左上一支細桿（0.03 × 0.3）頂著珍奶杯（`cylinder` 0.14 × 0.2，色 `TEA`）＋ 杯蓋 `dome`（白）＋ 吸管（細 box，珊瑚）＋ 杯身 3 顆黑珍珠小球；
   - 輪子：後方兩個 `torus` 半徑 0.09（比現在小），加一支木色推桿（後方斜出 0.35）；
   - 檯面上兩杯小珍奶（`cylinder` 0.05 高 0.08）。
   - 零件總數 ≤ 16；compound 合併後 draw call 跟現在一樣（1 個 mesh；沒有 glow）。`CART.w／d`、footprint、`PUSH_END`、老闆站位、立牌位置都不變（車身尺寸不變）。`tipped()` 翻倒的寫法照舊。
   - 目視：`npm run shot boba-blown` 加一張 ad hoc `boba-cart=auto=milk,baseball,boba&cam=boba`，報告附路徑。
3. **泡溫泉**（`landmarks.js`）：溫泉客改站進池裡——
   - 站位：池心半徑 0.3 的兩點（角度照 `BATHERS` 的 0.93、2.0），y ＝ 池水面（0.13）− 0.22（水淹到胸口，只露頭肩與手臂），面向池心；`rescue: false`（站位在 footprint 裡是故意的，同 token 淹水的泳客）。變異鼠在池前（`mutantAtSpring`）時改用 `BATHERS_NORTH` 的角度、同樣半徑 0.3（人在池裡，離池邊的變異鼠 ≥ 0.6）。
   - fidget：`'look'` 照舊（偶爾瞥一眼）。走進池子：名冊補人時從入口走到站位，最後一段走進 footprint（`authored` 站位已允許）；`gameInvariants` 的 walls 檢查對「站位本來就寫在 footprint 裡」的人本來就放行（roster.js `authored`）——確認 landmarks.bathers 符合那個條件（stand、沒有 rescue、站位在 footprint 裡）。
   - 老鼠泡溫泉（`rat.js SPRING_SPOTS` 半徑 0.62、5 隻）：溫泉客在半徑 0.3，離每隻老鼠 ≥ 0.25（算一次寫進註解與測試）。
   - 颱風躲雨（`typhoon.js nearestDoor`）：池裡的人照樣跑去小澡堂躲、回來再走進池裡（既有流程）。
   - `test/landmarks.test.js`、`test/rat.test.js`（外星局：溫泉客在池裡、不會走過變異鼠——原本「bathers make room」那題改成「溫泉客在池裡不動」）。
4. **火山重畫**（`landmarks.js` 新 builder `volcano`，取代 `frustum`＋圓盤＋橢球）：
   - 幾何：`CylinderGeometry(0.95, 1.45, 1.5, 12, 6)` 每個頂點加決定性亂數（`scene/random.js` 的 mulberry32 固定種子）徑向 ±0.08、高度 ±0.04 的抖動，頂點法線用 flat shading（`toNonIndexed()` 後 `computeVertexNormals()`），一個 `MeshStandardMaterial({ vertexColors: true, flatShading: true })`；頂點色：高度 0–0.55 沙色 `CLIFF`、0.55–0.9 深棕 `0x6b5a4e`、0.9–1 火山口邊緣更深 `0x4a3f38`，分層邊界也帶抖動。
   - 火山口：頂面往下凹 0.18 的碗（`CylinderGeometry(0.75, 0.55, 0.18)` 反面），裡面一片熔岩（`glow` 橘 `0xdb6a41`，`circle` 或薄圓盤）在碗底；熔岩邊緣 3 條熔岩痕從口緣往下流到高度 0.6（細長的 `box` 貼在斜面上、`glow` 同色）。
   - 既有的 4 顆石頭（`ico`）照舊；煙 `landmarks.volcanoSmoke` 照舊（`offsetY` 對齊新口緣）。
   - draw call：合併後 ≤ 現在（1 個不發光 mesh ＋ 1 個發光 mesh）；`npm run shot` 全部預算不變，`wide-end` ≤ 248。
   - `kit.js` 的 `frustum` 若沒有別人用就留著（101 還在用）。
   - 目視：ad hoc `volcano-new=auto=milk&cam=-1,5,-6,-2,1.2,-7.5`，報告附路徑（改前已有 `shots/volcano-now.png` 可對照）。
5. **飛彈警告**（`finale.js`、`src/scene/people.js`、`src/show/crowd.js`）：
   - 零件 `finale.beacon`（`flags.alarm && !flags.missile` 時）：101 頂（`stage.headOf('tower')` 之上 0.15）一顆小紅球（`glow` 紅）＋一道扁平的紅色光束（`CylinderGeometry` 半透明，長 3、從球心往外），繞 y 軸每秒 1 圈，光束亮度跟 `finale.flare` 同一個 `FLARE_HZ` 脈動；zoom 的全景裡看得見。
   - 新手勢 `duck`（`people.js`，`GESTURE_DUR.duck = 1.0`）：身體下蹲 0.08（整體 y −0.08、腿彎）、兩手舉到頭上（armL／armR 往前上抬到 −2.6 rad），0.15 s 進、0.7 s 停、0.15 s 回。
   - 劇本 `warning`：`B.apply(e, { only: ['finale.flare', 'finale.beacon'] })` → `B.focus('tower', { zoom: 0.9 })`（鏡頭先到 101 看警示燈 0.8 s）→ `B.together([shout, ...up.look])`（抬頭看紅光，照舊 1.2 s）→ `B.together(全島 duck 1.0 s)` → `up.release`；`B.focus('home')` 由飛彈那一段開頭的回全景接手。整段 ≤ 4.5 s；壞結局終局（警告＋飛彈）≤ 12 s、真結局 ≤ 22 s（`npm run pace -- --check` 的終局列）。
   - 測試：finale.test（view 有 beacon、warning 劇本拍序）、people.test（duck 姿勢數值）、pace 門檻。
   - 目視：ad hoc `warning-new=auto=milk,baseball,token,bulb,chip,typhoon,boba,rat&live=1&warp=<警告開始後 1.2 s>`（用 pace 的最後一輪秒數找 warp）。
