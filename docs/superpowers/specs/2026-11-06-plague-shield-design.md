# 鼠災整島、矽盾只在真結局、溫泉客逃離（2026-11-06）設計

使用者 2026-11-06 試玩影片（鮮奶 → 棒球 → 代幣 → 燈泡 → 晶片 → 老鼠 → 珍奶 → 颱風）：「跟你說的結果不一樣欸。並且鼠災結局很不明顯阿，我理想中的鼠災是整島都是老鼠。以及目前矽盾明明有了，關鍵時刻卻長不出來又不解釋實在很奇怪（我建議矽盾只有在真結局才會長）。隕石砸到溫泉裡時裡面還有人很奇怪。」

影片對照：格子編號 1–8 跟我給的順序一樣，規則也判定「大巨蛋鼠災」；但畫面只有隕石被吹進溫泉、兩隻老鼠在巨蛋門口——玩家看不出是鼠災。問題在演出。

接在 `2026-10-31-single-path-design.md` §8 R46 之後，記成 R47–R49。規則只動一條清單（`BAD_EPILOGUES` 加 `domeRats`）；其餘是演出與零件。

## R47 鼠災收尾：老鼠佔領巨蛋格、溢到橋上，人撤到隔壁格（2026-11-07 第三版）

- 第一版（計畫 21）整島 96 隻鼠群——使用者：「全島老鼠的效果太噁心，建議收回」「老鼠變異後下一級又變回老鼠，變異老鼠意義不明」。
- 第二版（計畫 22）只在巨蛋門口六隻、球迷退到門外——使用者手機截圖：「結果人都在，只有三隻老鼠。看不出來是鼠災。全島都是老鼠又太超過，感覺要折衷」，選了「老鼠也溢到橋上和隔壁格邊緣」。

定案（第三版）：
- 老鼠維持型態（第二版不變）：`packModel(lv, flags)`——Lv4 `alien` 綠色發光三眼、`cyber` 灰色天線、Lv3 普通；門口六隻名冊老鼠（`DOME_N`）照舊站 `GATE_FAN`。
- 鼠群 `rat.horde`：一個 `InstancedMesh`（`HORDE_N` 36 隻；幾何同計畫 21 的黏土鼠，顏色照型態——`alien` 是 `C.alien` 帶發光、`cyber` 灰、普通黏土色），從巨蛋門口湧出（`rush`，1.2 s；`place(nav)` 把落點挪到走得到的地面，live、跳過都做），落點只在三個區域：巨蛋格 `[-1,1]`（約 24 隻：半徑 0.6–2.0、巨蛋 footprint 外、彼此 ≥ 0.35）、巨蛋格通往三個鄰格（`[0,1]`、`[-1,0]`、`[0,0]`）的橋面（每座約 2 隻，`bridgeDecks` 的甲板點）、鄰格靠橋頭 0.8 以內（每格約 2 隻）。不再往其他地方撒。
- 人撤離：巨蛋格上的人（球迷 `baseball.crowd`、球員 `baseball.players`、接駁來的 `baseball.riders`、草皮 `baseball.lawn`）與這三座橋上的人，錯開 0.08 s 各自「！」、0.15 s 後以 2.0 m/s 跑過最近的橋，到鄰格離橋頭 ≥ 1.5 的點（`EVAC_SPOTS`：每個鄰格 3 個，走得到；多的人共用最近點），家搬到那裡（終態留在鄰格；RESET 重建）。工作人員 `baseball.staff` 留在門口追老鼠（`CHASE`）。其他格的人不動。
- 鏡頭：巨蛋門口 0.8 s（六隻冒出、鼠群開始湧）→ 全景（看得到巨蛋格一片綠、橋上有老鼠、人往隔壁跑）→ 停 1.0 s。整段 ≤ 5.5 s；終局（吹偏）≤ 16。
- 骨架動畫：名冊老鼠 6＋石堆島 2＋柴犬＝9 ≤ 12；鼠群是一個 draw call（手機 ≤ 150）。
- 截圖 `domerats`（`cam=baseball`）、`phone-domerats`。

## R48 矽盾只在真結局長出來

現況：晶片 Lv7 長天線、Lv8 罩子測試閃三下、隕石警告時 7–8 的罩子「試升失敗」——玩家看到罩子有了卻不擋，覺得沒道理。

改法：天線、罩子都只在晶片 Lv9（規則上就是擋下隕石的那一級）出現。Lv7、Lv8 改成「零件到了、施工中」：
- Lv7 「零件搭列車運到 101 腳下」：劇本照舊（列車進站、站務員敲一下、工程師抱著箱子走到 101 腳下），套用的新零件是 `chip.crates`——101 底座西南角三個木箱（`CRATE` 0.3 見方、堆兩層；footprint 一個小矩形，不擋走道）。
  - 定案：木箱放在 101 底座南緣正前方、西半邊（`CRATES_AT`；西南角外是走道出口）；抱箱子的工程師走到木箱前面（`CRATES_FRONT`，南 0.45、偏東 0.2，快步 4.0）、面向木箱時箱子出現。
- Lv8 「101 頂上搭起鷹架」：新零件 `tower.scaffold`（塔頂下方一圈細鷹架：奶油色 torus ＋ 四根短柱 ＋ 一支小吊臂；footprint false），劇本：回全景 → 鷹架閃白出現、101 腳下的工程師做 `build` 動作 1.0 s、全島抬頭看（`lookUp`）→ LEVEL UP（一般劇本 ≤ 3.5 s；Lv8 仍是 ◆ 可留 ≤ 6 s）。
  - 定案（修正輪 1）：四根柱高 0.9、立在最上一節的飾條上（頂帽底），環 scale 1.1 套在柱頂；工程師走到 101 腳下（`FOOT`）才敲。
- Lv9 「矽盾待命」：鷹架與木箱拿掉（縮下去），天線與罩子出現（既有 Lv9 劇本：罩子從地面長起、天線每 3 秒閃一圈）。
- 隕石警告：拿掉 7–8 的 `shieldFail`／`FAIL_WAIT`；`shieldSpec('test')`、`'fail'` 與 parts.js 的 `SHIELD_FAIL`、`failPose` 整段刪除；`tower.antenna` 只在 `lv.chip >= 9`。命中（hit）時木箱留在原地（零件沒裝上去就被撞了——這就是「矽盾未就緒」）。
- `STORIES.grow.chip[7]`、`[8]` 的句子改成上面兩句（只是資料，畫面不印字）。

## R49 溫泉客在隕石掉進池子前逃走

- 吹偏（deflect）的隕石劇本：隕石撞到塔頂被風吹偏的那一刻起（`FLIGHT`），兩位溫泉客從池裡爬出來、小跑（`DASH`）到池邊外 `BATHER_FLEE` 1.1 的兩個點（池子東側、面向池子），頭上「！」；水花之後跟大家一起「？」「♪」。
- 零件：`landmarks.bathers` 的站位照旗標決定——`flags.missile === 'deflect'` 時站在池緣外（`BATHERS_OUT`），其餘照舊泡在池裡；收尾的 `home` 把他們放回「現在的」站位（池緣外），不會再走回有隕石的池子。
- 命中、擋下兩種結果不動。
