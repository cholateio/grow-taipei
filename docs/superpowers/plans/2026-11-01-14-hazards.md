# 颱風雨與老鼠一直有效 實作計畫（計畫 14）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 使用者 2026-11-01：「我在颱風後放棒球和車站，雨繼續下，但怎麼沒有淹水？」「我在老鼠後放牛奶和珍奶，怎麼老鼠沒去破壞讓他們不能升級？」——同意改成災害在場期間一直有效。規則改完仍要**剛好一條全 MAX 順序**（順序可以跟現在不同）。

**Architecture:** 規則層 `src/rules/spec.js`＋`src/rules/engine.js`：颱風下雨期間（Lv1–2）之後放下的燈泡／代幣／棒球／珍奶當場套用颱風的那條檢查（鎖＋旗標＋故事句）；老鼠還在島上（Lv1–2，沒搭捷運）時之後放下的鮮奶／珍奶被咬，而且老鼠搭上捷運（Lv3）之前長不上去。求解器 `npm run check` 重找唯一解；演出層補老鼠咬珍奶的劇本與畫面。

**Tech Stack:** 原生 ES modules、`node --test`、求解器 `src/solver/run.js`（`enumerate`／`check`／`stats`）與收緊器 `src/solver/tighten.js`、無頭演出 `test/helpers/show.js`、`npm run pace`、`npm run shot`。

**Spec:** 本檔 §設計；上位設計 `docs/superpowers/specs/2026-10-31-single-path-design.md`（§3 正解表、§4 規則、§8 裁決延續 R29）。

## 設計（決定好的事）

1. **R29 颱風雨一直有效**：放下物品 X 的那一刻，若颱風已在場且 `lv.typhoon` 是 1 或 2（還在下雨；放晴是 Lv3），就對 X 跑颱風 `fx` 裡 `lock === X` 的那一條（燈泡 → blackout、代幣 → flooded、棒球 → domeFlood、珍奶 → cartBlown；X 剛放下是 Lv1，門檻條件必成立）。事件照現在的 fx 事件格式（`kind: 'fx'`、`cause: 'typhoon'`、`lock`、`flag`、`story`），排在 X 的 placed 事件之後、成長掃描之前。鮮奶、晶片、老鼠、颱風本身不受影響。規格寫法：typhoon 加 `rain: { while: and(min('typhoon', 1), max('typhoon', 2)) }`（或等價的宣告），引擎在 `turn()` 放下 X 之後檢查；不要把物品 id 寫死在引擎裡。
2. **R30 老鼠一直有效**：放下物品 Y ∈ {鮮奶, 珍奶} 的那一刻，若老鼠在場且 `lv.rat` 是 1 或 2（還在島上；Lv3 起搭捷運走了），老鼠咬它：立旗標 `bitten_<Y>`（引擎 flags）、發一個 fx 事件（`cause: 'rat'`、`flag`、`story: '老鼠咬了剛開的<名稱>'`），而且**只要老鼠還是 Lv1–2，被咬的 Y 不能升級**（成長掃描跳過它，也列在 wait 事件裡、`waits` 的 `for: ['rat']`——老鼠指標就會守在它門口）。老鼠升到 Lv3 那一刻起不再擋（旗標留著給演出看）。原本的「放老鼠時鮮奶 ≤2 就 −1」照舊。規格寫法：rat 加 `bite: { while: and(min('rat', 1), max('rat', 2)), targets: ['milk', 'boba'] }`（或等價），引擎通用處理。
3. **唯一解**：改完跑 `npm run check`。結果三種：
   - 剛好一條 → 記下新順序（可能跟現在不同），更新所有寫死舊順序的地方；
   - 零條 → 找出卡住的條件（多半是珍奶 Lv5「旗艦店等颱風過了」與晶片 Lv9 要颱風 3：颱風得在珍奶 ≥4 之後放、又要在第 9 回合前放晴），用 `npm run tighten` 的反向思路**放寬**最少的條件讓剛好一條成立；
   - 多條 → 用 `node src/solver/tighten.js` 的建議收緊到一條，挑最符合故事的那條子句。
   每一個條件改動都寫進設計 §8 R29／R30 並附理由。全 MAX 的結局仍是賽博龐克台北（ratBranch cyber）。
4. **演出**：
   - 雨中放下被鎖：沿用現有的鎖住反應（`turn.js lockBeats`：泳池、巨蛋泳池、攤車被吹走、大停電），不用新畫面；確認從 placed 到 fx 的拍序正常（鏡頭在 X 那格）。
   - 老鼠咬珍奶：新劇本 `rat.js` 的 fx（cause rat、`bitten_boba`）：一隻老鼠（`rat.pack` 最近的那隻）跑到珍奶攤車旁 → `sniff` → 攤車零件換成「被咬」的樣子（攤車側面一個深色缺口、地上兩顆掉出來的珍珠；`boba.js` 看 `flags.bitten_boba && lv.rat <= 2`，老鼠走了就恢復）→ 沒有 LEVEL DOWN（沒有降級）。老鼠咬鮮奶照舊（牛奶箱側躺），新的放下咬也用同一個畫面（`milk.js` 看 `flags.bitten_milk && lv.rat <= 2`，加上原本的 `meta.bitten`）。一級 3–4.5 s。
   - 被擋住期間老鼠守在被咬的那棟門口（`stage.troubleOf` 會自然選到它，因為它在 waits 裡）。
5. **測試**：
   - `test/engine.test.js`：雨中（颱風 1、2）放代幣／棒球／珍奶／燈泡 → 鎖＋旗標；颱風 3 放 → 沒事；颱風放下那回合的既有檢查不變。老鼠 1、2 時放鮮奶／珍奶 → 被咬、不長、wait 裡 `for: ['rat']`；老鼠升 3 那回合起照常長；老鼠 3 以上放 → 沒事；原本放老鼠咬鮮奶 −1 照舊。
   - `test/spec.test.js`：新欄位的形狀。
   - `test/solver.test.js`：唯一解、MAX 分布、正解的逐回合等級表（設計 §3）全部重算；EXAMPLE（`test/helpers/endings.js`）照枚舉重釘。
   - 所有寫死舊正解順序的地方（目前 8 處左右：`grep -rn "milk,baseball,token,bulb,chip,typhoon,boba,rat"` 與陣列寫法）換成新順序；`package.json` 的 shot 清單、`tools/pace.mjs`、`test/helpers/show.js SOLUTIONS` 等。
   - 演出：`test/rat.test.js` 老鼠咬珍奶劇本拍序、秒數；`test/boba.test.js` 被咬的樣子；live：一條老鼠先放、再放珍奶的順序整局演完不丟錯、`gameInvariants` 乾淨。
6. **節奏與截圖**：`npm run pace -- --check` 通過（各回合上限、◆ ≤ 8 s、終局 ≤ 22／12）；`npm run shot` 預算不變（`wide-end` 249／250 只剩 1，新畫面不准多 draw call——被咬的缺口與珍珠併進既有的 compound）。截圖清單裡用舊正解的 `auto=` 全部換成新正解，`warp=` 秒數重找。

## Review Focus
1. 雨中放下的鎖是在成長掃描**之前**（被鎖的物品當回合不長），而且不會在颱風放下那回合重複觸發——Task 1。
2. 被咬的物品在老鼠 Lv3 那回合起才長；老鼠 Lv2 → Lv3 跟被咬物品同一回合時的順序（老鼠先升還是被咬的先檢查）有測試釘住——Task 2。
3. 唯一解換了之後，所有寫死舊順序的測試、工具、截圖都換了，沒有殘留——Task 3。
4. 老鼠咬珍奶的畫面在老鼠走了之後恢復、不留缺口——Task 4。
5. 壞結局的終局秒數、各回合秒數仍在門檻內——Task 5。
