# 台北成長 — 看得見的因果與離島三段（設計）

日期：2026-10-28。使用者看了第二段錄影（`螢幕錄製 2026-10-28 213514.mp4`）後說：後期實在看不出「因為我放了這個，那個才升級」；GROW 系列會呈現「不升級的原因」；離島不夠豐富。
討論後使用者同意：每一級都要有觸發者、升級前先演原因、沒升級也要演（但**不要**主角「……」加幫手圖框那種泡泡版）、級數先留 61、離島每座分三段。

取代 `2026-10-28-choice-growth-design.md` §4 裡「升級怎麼演」的部分；規則條件（§3）由本文件 §3 重寫。飛彈、尾聲、標題卡照舊。

## 1. 意圖

玩家每放一個物品，畫面上要看得到它去影響了誰、誰因此長大；放錯順序時要看得到誰在等誰、為什麼沒長。
這是 GROW 的核心回饋：升級是互動的結果，不是時間到了自己長。

## 2. 目標、非目標、反目標

目標
- Lv3 以上沒有「自己長」：每一級的條件都提到至少一個別的物品（Lv2 可以自己長：剛放下那一回合的小成長）。颱風例外（天氣不是被誰觸發的）。
- 每個「有原因」的升級，先演**拜訪**：幫手物品的代表走到被升級的建築前互動，再閃白升級。拜訪是系統性的一拍，八個物品共用一套，不逐級手寫。
- 每個因缺幫手而沒長的物品，演**撲空**：它的代表走到缺的那個物品該在的地方（或自己的門口），做一個失望的動作，走回去。沒有泡泡、沒有圖框。
- 七座離島各分三段：空島 → 第一個碰到它的物品給它東西 → 更高的一級再加一層。
- 仍剛好兩條全 MAX 正解；跳過、reduced-motion、RESET 規則不變。

非目標
- 不減級數（61 級先留著；做完看一次，太擠再談）。
- 不逐級手寫互動劇本；各物品原有的升級劇本照舊，拜訪拍接在它前面。
- 不碰飛彈、尾聲、標題卡。

反目標
- 任何泡泡式的「原因提示」（圖框、「……」）。
- 回合長到不能忍：§6 的門檻。

## 3. 規則：每一級都有觸發者

原則：條件要說得出故事（誰來了、誰夠高了），寫成 `minLevel`／`present`；求解器再 AND 收緊到剛好兩解。下表是起點（`auto` 的級全部換掉；已經有條件的照舊），建造者用求解器調數字，不改故事方向：

| 物品 | 級 | 原本 | 改成 | 故事 |
|---|---|---|---|---|
| 鮮奶 | 4 兩層 | auto | `present('chip')` 或 `present('boba')` | 園區／珍奶店帶來家庭，學生變多 |
| 鮮奶 | 5 三層 | auto | `min('bulb', 2)` | 路燈亮了，開夜間部 |
| 晶片 | 8 矽盾測試 | auto | `min('bulb', 8)` | 海底電纜供電才能測 |
| 燈泡 | 3 霓虹 | auto | `present('boba')` | 攤車開了，夜市有人 |
| 燈泡 | 4 夜市 | auto | `min('milk', 3)` | 小學生放學逛夜市 |
| 代幣 | 3 大車站 | auto | `min('milk', 3)` | 學生通勤 |
| 代幣 | 4 環狀線 | auto | `present('chip')` | 工程師通勤 |
| 代幣 | 5 加車廂 | auto | `min('baseball', 2)` | 球迷 |
| 代幣 | 8 接駁車 | auto | `min('boba', 5)` | 小島分店要送貨 |
| 老鼠 | 2 一窩 | auto | `or(min('milk', 2), min('boba', 2))` | 早餐店／人龍的廚餘 |
| 老鼠 | 3 搭捷運 | auto | `min('token', 4)` | 有列車才搭（本來就隱含） |
| 老鼠 | 4 分岔 | auto | `or(min('chip', 3), min('typhoon', 2))` | 園區實驗室（賽博）或暴雨變異（外星） |
| 珍奶 | 2 人龍 | auto | `min('milk', 3)` | 學生排隊 |
| 珍奶 | 3 店 | auto | `present('chip')` | 工程師客群 |
| 棒球 | 2 木看台 | auto | `min('milk', 3)` | 少棒 |
| 颱風 | 2 登陸 | auto | 照舊 | 天氣 |

- 棒球 Lv3 大巨蛋原本只有 `max('token', 7)`（沒有幫手）：加 `min('milk', 3)`（少棒隊的孩子要先有）。
- 兩條正解**可以變**：剛好兩條、一賽博一外星即可（傾向保留老鼠第 7、颱風第 8，不強求）。表裡的某一列收不到解時可改門檻數字或換成同一故事方向的另一個幫手；要整列拿掉就記裁決。
- 預設跳級（`up[n−1] ∧ up[n]`）、鮮奶 steady、放下當回合可長、`CLOSING_TURNS` 1 照舊。
- 求解器驗收照舊；PACING 若撐不住記裁決。改了哪些數字寫回本節。
- 引擎多給每個 grow 事件 `via`（已有：條件裡的幫手）與每個等待的物品 `wait.waits[]`（已有）；演出層靠這兩個。
- **實作結果（計畫 6 任務 1，2026-10-28）**：表的 15 列與棒球 Lv3 的 `min('milk', 3)` 都照做（Lv2 的老鼠、珍奶、棒球也換掉了，沒有退回 auto）；`via` 改成「這次真的成立的幫手」（`satisfiedHelpers`：or 只算成立的那幾支、and 全列、跳級是兩級的聯集）。兩條正解**沒有變**：鮮奶 → 棒球 → 燈泡 → 代幣 → 晶片 → 珍奶 → 老鼠 → 颱風（賽博）、鮮奶 → 棒球 → 代幣 → 燈泡 → 晶片 → 珍奶 → 老鼠 → 颱風（外星）；求解器驗收全過、PACING 不用放寬（MAX 落在第 7、8、9 回合，最後一輪 4 個）。和表不一樣的四格（都是求解器逼出來的，故事方向不變）：
  - 鮮奶 4：`present('chip')` 或 `present('boba')` → 再加 `present('bulb')`、`present('token')`（路燈、捷運也帶家庭來）。鮮奶要第 1 個放、一回合一級沒有餘裕，第 3 回合就要到 4；燈泡要第 4 個以前放（鮮奶 5）、晶片和代幣要第 5 個以前放，珍奶排不進前 5；第 3 個放晶片的那條晶片只到得了 8——只認晶片／珍奶就零解。
  - 燈泡 3：`present('boba')` → `present('token')`（捷運站出口的人潮，霓虹點起來）。珍奶一定第 6 個以後放，等它霓虹晚兩三回合，海底電纜（燈泡 8）趕不上晶片 6，零解。
  - 代幣 4：`present('chip')` → `or(present('chip'), min('milk', 5))`（工程師或國中生通勤）。只認晶片的話晶片放第 8 個時代幣卡在 3，晶片變樞紐（物品 v2 §2 反目標的報告項）。
  - 代幣 8：`min('boba', 5)` → `min('boba', 2)`（攤車有人龍就要送貨）。≥5 時代幣第 7 回合到不了 8、棒球跟著晚一回合，MAX 擠成兩個回合、最後一輪 5 個（PACING 不過）。
  - 副作用：EXAMPLE.hit 變成 鮮奶 → 晶片 → 燈泡 → 代幣 → 老鼠 → 棒球 → 颱風 → 珍奶（矽盾未就緒＋鮮奶過期）；EXAMPLE.deflect 順序不變，標題從大停電變成捷運淹水（燈泡長得快，颱風登陸時已經過了 4）。隨機順序平均 MAX 2.36 → 1.12；「珍奶糖分超標」仍到得了（附註），但不再當標題（珍奶長人龍要鮮奶 ≥3）。

## 4. 拜訪（有原因的升級怎麼演）

每個 `grow` 事件若 `via` 非空，劇本前面插一段拜訪：

1. 鏡頭對著被升級的物品那一格（照舊的 focus）。
2. 幫手的代表（`via[0]` 那個模組的 `script.rep`）從它現在的位置走到被升級物品的**拜訪點**（各模組 `visitSpot(n, s) → { x, y, z, r }`：這一級的建築正面、y 是那一格的地面 `cellTop`，同 5b 之前的 `rushSite` 形式），站在 `frontOf(spot, r, nav)`。走路上限 `VISIT_WALK` 1.5 秒：走不到就在原處閃白、換到路上離站位剛好 1.5 秒的那一點再閃白、走滿 1.5 秒過去（至少 0.6 m；裁決 R3、R4）。◆ 關鍵級**也**插拜訪（原因才是重點；◆ 自己的劇本仍 ≤ 8 秒，拜訪另外量）。跳級的第二級不插（同一回合的第一級已經拜訪過，幫手相同）；登陸後的 indoors 事件不插（人都躲著）。
3. 互動 0.8 秒：代表面向建築做 `knock`（敲門／遞東西）；被升級物品若有自己的代表且在場，面向幫手 `wave`。
4. 幫手轉身要走的那一刻冒「♥」（0.6 秒，跟著他走；裁決 R4：跟走回日常（`home`）一起開始，不另外停 0.6 秒）。
5. 接著演這一級原本的劇本（閃白、LEVEL UP）。

- 引擎的 `via` 改成「這一次真的讓條件成立的幫手」（`or` 只算成立的那一支；跳級算兩級成立的幫手的聯集，照 ORDER）。
- 幫手沒有代表（颱風；電工在風車島上時的燈泡；鮮奶 Lv1–2 沒有小孩；代幣 Lv1 沒有站務員）或代表藏起來（登陸後）→ 不插拜訪。建造者可以給燈泡在 Lv7 之後補一位留在主島的電工（人數預算 ≤ 30 允許才加），否則略過。
- 沒有人拜訪颱風，颱風也不拜訪別人（天氣）。
- 同一回合同一個幫手拜訪多個物品：每次都走（最多 2 次，之後只演閃白；裁決 R2，原本 3——第三次重複，外星第 6 回合站務員一回合跑三趟）。真的演了才算一次（代表不在、在劇本手上而略過的不算；裁決 R3）。
- 換位置一律閃白（裁決 R3）：走不到的幫手在原處閃白 0.15 s（裁決 R4：跟物品之間的空拍一起演）、換到路上離拜訪點剛好 1.5 s 的那一點再閃白，走滿 1.5 s（至少 0.6 m）；回家的路超過 2 × 1.5 s 的，拜訪完背景走回出現的那一點、閃白、換回原處再閃白（名冊的 `leave`，模式 `away`）；其他的自己走回去（`roster.home(m, { hurry })`，裁決 R5：走路速度、焦點不在他家那一格也照走；巡路的人接回折線上離他最近的那一點）。
- 跳過時 ♥ 不冒（0 秒拍，時間軸跳過期間 `ctx.skipping`）；已經冒出來的由跳過的 snap 清掉。
- 每段拜訪 ≤ 3.5 秒真實時間，pace 與各物品測試把它當獨立一段量（mark 的 info 標 `visit`），不算進那一級自己劇本的 4.5 秒。
- 60 秒上限只在 `pace --check` 的幾條固定順序上驗（兩條正解與 EXAMPLE），不在遊戲裡即時裁剪；拜訪走路上限與「同一幫手最多兩次」（裁決 R2）是遊戲裡的規則。

## 5. 撲空（沒升級怎麼演）

引擎的 `wait` 事件列出每個等不到幫手的物品與它缺的幫手。每回合最多演兩段（依 ORDER 取前兩個）：

1. 鏡頭平移到代表那一格（跟走路一起演）。
2. 它的代表走到缺的幫手（`for[0]`）那裡：幫手還沒放 → 錨點旁的空地（可走、離建築本身 ≥ `MISS_CLEAR` 0.3 m）；放了但不夠高 → 那個建築這一級拜訪點的正面（跟拜訪站同一個位置）。
   目標點那一格跟代表那一格同一格或相鄰、走得到、路線 ≤ `MISS_WALK` 1.8 秒才走；否則（太遠、幫手是颱風、幫手這一級在離島上）走到自己門口；
   自己門口也超過 1.8 秒 → 往門口走 1.8 秒、在路上失望；自己這一級沒有主島上的門口、走不過去 → 原地失望。撲空不換位置、不閃白。
3. 面向目標，失望動作 `sigh` 1.0 秒（小人：頭低下、雙手垂、腳不動；模型成員：原地轉一圈）。沒有泡泡。
4. 走回日常（`hurry`，同拜訪）。

- 每段 ≤ 3 秒真實時間（`MISS_WALK` = 3 − 1.0 − 0.2 幀的餘裕 = 1.8）。等待圖框（舊的提示泡泡）拿掉。
- 代表叫不到（沒有、藏起來、在劇本手上、拜訪完正走回去 `away`、不在主島上）→ 整段 0 秒：連物品之間的空拍也不等，下一個事件的空拍與平移照撲空之前的帳（不多空一拍、鏡頭本來就在那一格不再平移；任務 6）。
