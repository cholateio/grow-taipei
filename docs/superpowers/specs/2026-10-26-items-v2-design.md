# 台北成長 — 物品階段重寫（v2）設計：8–10 級、跳級、離島鏈

日期：2026-10-26　作者：使用者（概念、階梯口味、離島鏈）＋ Claude（整理、條件草案、素材清單；標「我的決定」處可推翻）
狀態：草稿，待使用者審閱。取代主規格 `2026-10-24-grow-taipei-design.md` §5（八個物品）與 §6.2 的「每回合最多升一級」；§8 結局照舊，只把矽盾的來源改成看得見的離島鏈。

## 1. 為什麼改

使用者第二段錄影（2026-10-26）的結論：現在每個物品 3–6 級，故事說不完，建築變化也不明顯。GROW 系列的物品都是 8–10 級起跳，而且：

- 晚放的物品可以**跳級**：條件對了一回合升兩級，演出上是連續兩個 LEVEL UP。
- 有些物品**要等別人到某級再放才有意義**：放早了只會慢慢長甚至卡住。
- 全部發展完還有一段額外的小故事，多半壞結局，少數好結局（我們：矽盾擋飛彈）。

## 2. 目標、非目標、反目標

目標
- 八個物品各 8–10 級（颱風例外 4 級，它是考驗不是發展），每一級都是一句話就看得見的變化。
- 「捷運通離島 → 風電與燈塔啟動 → 晶片廠通電 → 矽盾」是看得見的主線，不再只是規則裡的條件。
- 全島長滿時熱鬧：人多、飛天車、霓虹、離島都在動。
- 仍然剛好兩條正解，分別走賽博與外星；跳級讓晚放的物品追得上。

非目標
- 不加第九個物品；不改八個物品的名字與圖示；不改結局的判定（§8.2 全 MAX 才是真結局）。
- 不重做演出層的機制（鏡頭、閃白、走路進場都沿用 3.7／3.8／3.9）。

反目標
- 晶片不能變成樞紐：不選晶片，其他物品也要長到 7 級以上。
- 每回合不能比現在更長：一級 3–5 秒，只有關鍵節點可以 8–10 秒。

## 3. 規則：跳級與「放的時機」

- 每回合每個物品：物品在 n−2 級且**跳級條件** `jump[n]` 成立 → 一次升到 n（+2，記兩個 grow 事件；跳過的那一級不看它的 +1 條件，跳級就是捷徑）；否則 **+1 條件**（`up[n]`）成立 → +1；否則不動。沒有「同一回合兩次 +1」這種事（我的決定）。
- 一回合一個物品最多 +2。引擎掃描到不動為止（照舊）；安全上限 64 次。
- **放下去那一回合也會長**（待使用者決定，見 §11 問題 1）：第 8 個放的只剩 3 個倒數回合，照「當回合不長、每回合最多 +2」最多到 Lv7，沒有任何順序能全滿。建議改成放置當回合就依條件 +1／+2（GROW 裡最後放的東西條件都齊了，放下去就連跳幾級）。這會推翻 2026-10-25「剛放下的物品當回合不升」的決定。
- 「一回合最多 8 個事件」不是求解器的規則，是演出層的節奏門檻（§6）；跳級的兩個 LEVEL UP 算一段劇本。
- 「要等別人到 X 級再放才有意義」用現有的條件語言寫：Lv2 的 `up` 就要求別人的級，放早了 Lv1 停著等（stall 事件照舊可以演「……」泡泡）。
- 時間窗口（「要趕在 X 之前」）保留：棒球大巨蛋要趕在捷運通車前。
- 倒數回合仍是 3；11 回合裡一個物品最多 +1×11 或靠跳級更快，所以 10 級的物品不必第一回合就放。
- 求解器（§6.5 的六條）全部保留；第 1 條「剛好 2 種順序全滿」是硬條件。`tighten.js` 只會把條件收緊（解變少），所以下表要先鬆到至少有兩條解，再收到剛好兩條；建造者第一步先確認鬆表有解。
- 反目標「晶片不是樞紐」的量法（我的決定）：晶片放第 8 個時，其餘七個物品在某一種順序裡都能到 ≥7。這是求解器的報告項，不是硬門檻。
- 老鼠分岔（照舊 `ratBranch` 旗標在 Lv4 決定）：「泡過溫泉」= 老鼠到 Lv3 時代幣 ≤1（記 `soaked` 旗標）；搭過捷運的老鼠走不了外星路線。外星側 Lv6 的跳級用颱風 Lv3（彩虹後石堆島出現綠光）。
- 壞結局旗標以 `rules/spec.js` 現況為準、改數字：鮮奶過期 = 鮮奶 ≤5 且放下 6 回合；糖分超標 = 珍奶到 Lv4（噴泉）時鮮奶 ≤1。

## 5. 離島鏈（主線）

```
代幣 Lv6 通車到離島 ──→ 燈泡 Lv7 電工搭車去開風車、燈塔亮 ──→ 燈泡 Lv8 海底電纜
                                                                   │
珍奶 Lv6 燈塔島旗艦店（支線的副產品）                                ▼
                                                   晶片 Lv6 廠房通電 → Lv7 天線 → Lv8 測試 → Lv9 待命
                                                                                            │
                                                                            結局：飛彈 → 矽盾擋下（§8.1）
```

- 風車與燈塔**開局是暗的、不轉的**（衛星島 view 改：燈塔 `lit` 與風車 `spin` 都看燈泡 ≥7，不再看燈泡 ≥2；颱風時風車仍被吹得狂轉，那是風不是電）。
- 「有人前去啟動」是燈泡 Lv7 的劇本：電工走到車站 → 搭列車到風車島（trainStop 到支線終點）→ 走到風車下揮鋤頭／按開關 → 風車開始轉、燈塔亮起 → 鏡頭回全景。
- 矽盾的罩子：半圓形、半透明淡藍、邊緣有六角格紋閃爍（我的決定：六角格紋呼應島的六角格）。Lv8 測試閃三下，Lv9 常駐淡輪廓，結局時全亮擋飛彈。

## 6. 演出長度（不能比現在長）

- 一級的劇本 3–5 秒：走到位、一個動作、閃白換零件、LEVEL UP。跳級是兩個 LEVEL UP 連著出（第二個不重走路）。
- ◆ 關鍵節點 8–10 秒，鏡頭可以回全景定格。
- 門檻照舊 8–50／倒數 ≤22（3.8 的數字）；一回合最多 8 個事件，8×5 ＋鏡頭 ≈ 45 秒，剛好。
- 既有 3.7／3.8 的小旅程劇本要縮：每個物品保留一兩段最好看的，其餘改成短版。

## 10. 建造順序建議

1. 規則與求解器（`rules/spec.js` 新階梯＋ `jump`；引擎支援一回合 +2）→ `npm run check` 綠。
2. 視覺標準件（鮮奶三級）→ 使用者看過。
3. 其餘七個物品的 view 與短劇本，一次一個物品。
4. 離島鏈的三段長劇本與矽盾罩。
5. 節奏驗收、截圖、文件。
