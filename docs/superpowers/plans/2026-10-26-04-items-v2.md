# 計畫 4 物品階段 v2（級數分層、跳級、離島鏈、素材換新）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 八個物品從 41 級改成 61 級（鮮奶 10、代幣 10、晶片 9、燈泡 9、棒球 8、珍奶 7、老鼠 5、颱風 3），每級看得見；引擎支援跳級（+2）；離島鏈（通車離島 → 風電／燈塔 → 廠房通電 → 矽盾）看得見；建築換成 CC0 低多邊形模型、重上色票；仍剛好兩條正解。

**Architecture:** 規則資料 `rules/spec.js` 重寫階梯與條件，引擎加 `jump[n]`（n−2 級且條件成立 → +2，記兩個 grow 事件）與颱風延後規則，求解器六條驗收不變、加一條「晶片放最後其餘能到 MAX−1」的報告項。素材：`tools/fetch-assets.mjs` 從 Kenney／Quaternius 鏡像抓指定檔案進 `assets/`，載入器把一個 glb 合併成一個 mesh（頂點色＝色票）以守 draw call。演出層只加一條規則：同一回合同一物品連續兩個 grow 事件 → 第二個只演 LEVEL UP。然後一次一個物品重寫 view 與短劇本（3–5 秒），離島鏈三段長劇本與矽盾罩最後做。

**Tech Stack:** 原生 ES modules、three.js（vendor，`BufferGeometryUtils.mergeGeometries`）、node:test、headless Chromium（`npm run shot`）、curl（抓素材）。

**Spec:** `docs/superpowers/specs/2026-10-26-items-v2-design.md`（本計畫依據；§3 規則、§4 階梯、§5 離島鏈、§6 長度、§7 素材）；主規格 `2026-10-24-grow-taipei-design.md` §6.3（颱風檢查）、§6.5（求解器）、§8（結局）照舊；演出層規格 `2026-10-25-show-layer-design.md` §13／§14 的機制沿用。

分支：從 `main`（計畫 3.9 併入後）開 `items-v2`。

- `npm run check` 六條驗收全部保留（剛好 2 條正解、一賽博一外星、七個壞結局都到得了、晶片未 MAX ≥ 30%、平均 MAX ≤ 3.5、貪婪到不了真結局、同回合 MAX ≤ 3 且 MAX 回合 ≥ 4）。

- 人數預算（使用者 2026-10-26 看了 Task 4 之後的要求：整體人數減少、珍奶人龍太容易卡住）：全島同時可見的名冊成員 ≤ 30、單一格 ≤ 8；珍奶人龍 ≤ 4、不再有閒晃觀光客；棒球觀眾 Lv4 3 人、Lv5 4 人、Lv7 6 人、草皮 1 人；鮮奶節多的小孩 3 人（不是每格一個）；島民 4＋溫泉客 2。各物品任務改到自己的數字，Task 12 驗收總數。

- 文件與註解：台灣用語的繁體中文。

## Review Focus

1. **跳級落在被鎖或 MAX−1 的物品**：`jump[n]` 不能越過 `locked`，n > max 時不跳（Task 1 測試）。
2. **跳級的兩個 grow 事件在演出層**：第二個事件沒有劇本也不能空白——至少 LEVEL UP；跳過（skip）時兩級一起到位（Task 2 測試）。
3. **颱風最後放**（第 8 個）：Lv2 的全島檢查仍在倒數回合執行，鎖住燈泡／代幣時那兩個物品已 MAX → 鎖不影響結局（Task 1 測試：颱風第 8 的正解仍全滿）。
4. **glb 合併後的材質名稱**：`tint` 依材質名稱上色，合併後名稱消失 → 要在合併前上色（Task 3 測試：合併後頂點色等於色票）。
5. **風車與燈塔開局是暗的**：舊的 `sat.lighthouse`（燈泡 ≥2 亮）測試要改；颱風時風車狂轉仍要有（Task 11 測試）。

## 共用介面

```js
// rules/spec.js
ITEMS[id] = { name, max, up: { n: cond }, jump?: { n: cond }, fx?, onLevel?, stall?, delay?: { n: cond } }
//   jump[n]：物品在 n−2 級且 cond 成立 → 升到 n（兩個 grow 事件，第二個帶 jump: true）
//   delay[n]：cond 成立時第 n 級要多等一回合（颱風賴在巨蛋：delay[3] = min('baseball', 3)）
// rules/engine.js：turn() 裡每物品每回合：先試 jump[lv+2]，再試 up[lv+1]；grow 事件多 `jump: true`
// solver/run.js：check() 多一行報告（不計入失敗）：晶片放第 8 時其餘七個在某順序能到 max−1
// show/turn.js：同一回合同一物品的第二個 grow 事件（e.jump）→ 劇本 = [B.apply(e), B.levelUp(item)]，不加 focus、不加 GAP
// scene/assets.js：spawn(path, { tint, glow, merge = true }) → 一個 glb 合併成一個 Mesh（頂點色），draw call 1
// tools/fetch-assets.mjs：讀 tools/assets.json [{ source: 'kenney'|'quat'|'kaykit', pack, files: [...], into }] → 下載、解壓、只留 files、追加 LICENSES.md 一列
// actors：每個物品 view(lv, flags, meta) 回 { key: part }，script.grow[n]；◆ 節點可回自己的 focus 拍
```
